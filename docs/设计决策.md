# A1 设计决策

记录日期为 2026-11-06。原方案日期保持原样，A1 实际检查使用本次日期。

初赛选择显式同步状态机。当前仅单助手顺序执行，业务状态、保存事实与上下文修订需要直接核对。第一阶段实现独立契约和 SQLite 约束，后续执行器依据模型动作推进任务。该状态机负责执行流程，用户意图和动作决策仍由实际模型完成。LangGraph 作为后续编排候选，迁移时保留 ports 和 operations 的业务语义。

任务增加 cancelled 终态，用于用户明确取消旧任务后处理同企业其他月份。running、waiting_user、blocked 皆为未完成，数据库部分唯一索引覆盖三者，按用户和企业计数。新会话复用任务，session_id 不进入唯一任务约束。

金额以整数分存储，原始 Excel 数值先转十进制字符串，再调用 to_cents；输入明细超过两位小数时报告导入错误。所有汇总从整数分计算，最终格式化为两位小数。Excel 说明页的核对汇总不作为业务数据导入。

请求去重记录独立于会话消息。用户与 request_id 形成请求唯一键，保存完整规范化参数供后续判断重复请求或参数冲突。operation_id 绑定任务范围及对象；同对象最多一个 prepared/dispatched/unknown 操作。A1 已建立存储约束，实际请求重放、状态迁移校验、业务工具写入和回查在 A3 完成。

数据库使用短事务和应用内 RLock，A/B 共用同一个 Database 实例。数据库约束还防止跨连接的双未完成任务及双未决操作。后续按会话协调执行器；全局写锁仅用于受控修改，模型和网络调用在锁与事务之外，提交前重新读取关键状态。

规则按企业展开作用域。R001、R004 各有两个企业作用域行，R002 有两个版本，R003 有一个版本；若每份规则作为一个条目导入，应得到七个作用域行，仍对应五个规则版本。跨企业相同规则的内容更新应在同一事务内完成。revision 用于失效校验，version 表示业务文档版本。

正式模型 Key 和端点尚未接入。A1 无实际模型调用；上下文构建与 B 的服务通过 Protocol 约定，接口定义本身不算功能已实现。未来独立上下文服务、Java 后端、Next 前端、Redis/Celery 与 PostgreSQL 按方案的产品化阶段另行实施。
